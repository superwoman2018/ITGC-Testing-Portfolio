# 01 — ITGC Test of Controls: Change Management

**Framework:** IT General Controls (ITGC), relevant to SOX/financial-statement
audit support and Big 4 IT Audit methodology
**Core skill demonstrated:** The distinction between control *design* and
control *operating effectiveness* — and drawing an honest conclusion from a
sample that isn't perfectly clean.

## What's in this folder

| File | What it is |
|---|---|
| `scenario.md` | Why Change Management, why the exceptions are left in, and the judgment call behind the final conclusion |
| `deliverables/CloudNative_ITGC_Change_Management_Walkthrough.docx` | Control objective, walkthrough narrative, sample methodology, and the exception/conclusion writeup |
| `deliverables/CloudNative_ITGC_Change_Management_Test_Sample.xlsx` | The actual 25-item test-of-sample workpaper, attribute by attribute |

## How to read this

Start with the walkthrough document — Section 2 shows the design assessment
(is the control built correctly), and Section 5 is where the sample results
turn into an actual conclusion. Then open the test sample spreadsheet to see
the item-by-item attribute testing behind that conclusion, including the two
flagged exceptions (rows 14 and 25).

## Disclaimer

This is a portfolio exercise for a fictional company, built to demonstrate
ITGC testing methodology — not a real audit engagement, and not a substitute
for testing performed under a real audit firm's methodology and quality
standards.
